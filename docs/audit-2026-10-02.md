# NvJup audit — 2026-10-02

Baseline: `f3cac6f`. Scope: highlighting after formatting, source/save lifecycle,
and regression coverage across the plugin. No user notebooks or configuration
were changed. Background delegation failed before execution; the audit continued
in the parent session with the user's approval.

## Unified bug list

| ID | Severity | Finding | Status / evidence |
| --- | --- | --- | --- |
| A001 | High | Full composite-buffer replacement collapses cached Tree-sitter extmarks. Unchanged cells lose highlighting after formatting; replacement without source changes can affect all cells. | **Fixed**: invalidate the projection cache in `Notebook:replace_buffer`. New Stage 2 regression failed before the fix (Markdown highlights disappeared), passed afterward. It checks nonempty capture ranges, not merely extmark count. |
| A002 | Medium | A thrown Conform/configuration exception aborts notebook save and leaks its scratch buffer. | **Fixed**: protect the formatter invocation, clean the scratch buffer and report the error while saving original source. New Stage 1 test simulates the exception and verifies saved source and cleanup. |
| A003 | High | Atomic save recreates a private `0600` file with default `0644` permissions, potentially exposing notebook content. | **Fixed**: exclusive private `mkstemp`, checked writes/close, preserve existing permission bits before rename. Reproduced `rw-------` → `rw-r--r--` before the fix; regression verifies preservation. New files remain private. |
| A004 | Medium | Saving a notebook through a symbolic link replaces the link itself and leaves its target unchanged. | **Fixed**: resolve existing symbolic links and atomically update the target. Dangling links are preserved and return an error. Regression covers both cases. |
| A005 | Low | Python notebook-syntax detection is line/regex-based: a literal or comment containing `<YOUR CODE HERE>` or `<...>` is treated as a placeholder, so valid Python may be skipped by formatting. | **Open / deferred**: `has_notebook_only_syntax` in `cell_tools.lua` matches text without tokenization. No source loss; automatic/manual formatting can be skipped for such a cell. A syntax-aware detector is needed rather than further broad regex rules. |

## Audit coverage and limitations

Inspected formatting, notebook replacement/save, Tree-sitter caching, feature
refresh, atomic-write permissions/symlinks, trust identity and local-execution
policy, remote path/auth validation, local filesystem operations and cleanup
entrypoints. Existing tests exercise lossless metadata/output preservation,
editing/navigation/comments/indentation, shadow LSP/completion, RPC limits and
cancellation, real local kernel execution, rich output and animations,
Plotly/Bokeh, widgets, trust/network restrictions, remote transport/files and
Colab flow simulations.

This is not a proof that the plugin is bug-free or a line-by-line independent
security review. Live Google Colab authentication/allocation, an external user's
Jupyter server, SSH transport and visual Kitty/Awrit interaction were **not**
retested in this audit. Automated/mock coverage of these paths is not equivalent
to live external-service validation. The `nvjup: ipykernel is unavailable`
notification in Stage 8 is an intentional negative-path test; the suite exits 0.

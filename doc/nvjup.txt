1. INTRODUCTION                                  *nvjup-introduction*

nvjup opens nbformat 4 *.ipynb files as editable notebook cells. Cell headers,
borders, execution counts, and saved outputs are rendered using extmarks and
virtual lines. Structural marker lines remain in the buffer for reliable undo
and saving, but are concealed in normal use.

==============================================================================
2. SETUP                                                   *nvjup-setup*

With a plugin manager, call:

>lua
  require("nvjup").setup({})
<

Options include:

>lua
  require("nvjup").setup({
    border_width = 88,
    render = {
      outputs = true,
      max_output_lines = 12,
      markdown = true,
      right_border = true,
    },
    treesitter = {
      enabled = true,
    },
    sidecar = {
      -- Python containing jupyter_client; false auto-detects one.
      python = false,
      command = false,
    },
    kernel = {
      default_name = "python3",
      shutdown_on_close = true,
    },
    execution = {
      repeat_policy = "queue", -- queue, cancel, or replace
      stop_on_error = true,
    },
    lsp = {
      auto_start = true,
      -- false enables automatic .venv/venv discovery.
      python_path = false,
      -- Python defaults to Pyright and Ruff when installed.
    },
    keymaps = {
      next_cell = "]c",
      previous_cell = "[c",
      -- Set any action to false to disable its mapping.
    },
  })
<

3. NAVIGATION                                           *nvjup-navigation*

]c                      Next cell.
[c                      Previous cell.
]C                      Next code cell.
[C                      Previous code cell.
ic                      Inner-cell text object.
ac                      Around-cell text object, including its marker.

Counts are accepted by cell motions. Navigation adds the previous location to
the jumplist.

5. LANGUAGE TOOLING                                        *nvjup-language*

Each code language has one hidden shadow document, allowing language servers
to see definitions and references across code cells. Markdown and raw cells
are excluded. IPython magics are replaced by syntax-safe placeholders only in
the shadow document.

Tree-sitter parses each cell in its own language and projects highlight
captures into the visible composite buffer. Missing parsers degrade cleanly.

When nvim-cmp is installed, nvjup adds a buffer-local `nvjup` source because
the ordinary `nvim_lsp` source cannot see clients attached to hidden shadow
buffers. Existing completion sources remain enabled. Pyright automatically
uses a project-root .venv or venv unless `lsp.python_path` overrides it.

The default LSP mappings mirror ordinary code buffers:

gd                      Definition.
gD                      Declaration.
gi                      Implementation.
<Leader>D               Type definition.
gr                      References.
K                       Hover.
<Leader>ls              Signature help.
<C-Space>               Completion in Insert mode.
<Leader>ra              Rename across code cells.
<Leader>ca              Safe code action.
<LocalLeader>ls         Document symbols.

Diagnostics, semantic tokens, locations, and safe WorkspaceEdits are mapped
back from shadow buffers. Edits crossing a cell boundary, synthetic separator,
or IPython placeholder are rejected.

6. KERNEL EXECUTION                                       *nvjup-execution*

Kernel transport runs in a separate Python jupyter_client sidecar. It does not
use pynvim or python3_host_prog. The sidecar starts lazily on first execution
and uses the notebook kernelspec name or `kernel.default_name`.

Batch commands snapshot cell IDs, source, and revisions, skip non-code cells,
and execute sequentially. `execution.stop_on_error` cancels the unsent tail of
a failed batch. Editing a running snapshot preserves its output but marks it
stale with [*]. Output changes and execution counts are persisted by :write.

The sidecar routes stream, execute_result, display_data, update_display_data,
clear_output, error, and input_request messages. Normal stdin uses vim.ui.input;
password input uses inputsecret(). Interrupt and restart are explicit actions.

Header states are [ ] not executed, […] queued, [▶] running, [?] waiting for
input, [!] failed, [×] cancelled, and [*] stale. Completed cells show their
numeric execution count.

:NvJupClearAllOutputs   Clear every output and execution count.

:NvJupLspStatus         Show shadow documents and attached clients.

8. CURRENT LIMITATIONS                                  *nvjup-limitations*

Stage 3 executes cells and persists standard nbformat outputs, but rich static
images still use capability placeholders. Kitty image placement and interactive
Plotly/Bokeh are scheduled for later stages. Remote Jupyter Server attachment
and kernel-backed completion are also later work. Completion uses nvim-cmp when
available and Neovim's built-in completion UI as a fallback.

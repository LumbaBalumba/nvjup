1. INTRODUCTION                                  *nvjup-introduction*

nvjup opens nbformat 4 *.ipynb files as editable notebook cells. Cell headers,
borders, execution counts, and saved outputs are rendered using extmarks and
virtual lines. Structural marker lines remain in the buffer for reliable undo
and saving, but are concealed in normal use.

==============================================================================
2. SETUP                                                   *nvjup-setup*

With a plugin manager, call:

>lua
  require("nvjup").setup({})
<

Options include:

>lua
  require("nvjup").setup({
    border_width = 88,
    render = {
      outputs = true,
      max_output_lines = 12,
      markdown = true,
      right_border = true,
      images = {
        enabled = true,
        backend = "auto", -- auto, kitty, chafa, or text
        max_width = 64,
        max_height = 24,
        max_bytes = 10 * 1024 * 1024,
        max_pixels = 16 * 1024 * 1024,
        conversion_timeout_ms = 10000,
      },
    },
    treesitter = {
      enabled = true,
    },
    sidecar = {
      -- Python containing jupyter_client; false auto-detects one.
      python = false,
      command = false,
    },
    kernel = {
      default_name = "python3",
      -- false prefers project .venv/venv, then a system Python.
      python_path = false,
      system_python = false,
      shutdown_on_close = true,
    },
    execution = {
      repeat_policy = "queue", -- queue, cancel, or replace
      stop_on_error = true,
    },
    lsp = {
      auto_start = true,
      -- false enables automatic .venv/venv discovery.
      python_path = false,
      -- Python defaults to Pyright and Ruff when installed.
    },
    keymaps = {
      next_cell = "]c",
      previous_cell = "[c",
      -- Set any action to false to disable its mapping.
    },
  })
<

3. NAVIGATION                                           *nvjup-navigation*

]c                      Next cell.
[c                      Previous cell.
]C                      Next code cell.
[C                      Previous code cell.
ic                      Inner-cell text object.
ac                      Around-cell text object, including its marker.

Counts are accepted by cell motions. Navigation adds the previous location to
the jumplist.

5. LANGUAGE TOOLING                                        *nvjup-language*

Each code language has one hidden shadow document, allowing language servers
to see definitions and references across code cells. Markdown and raw cells
are excluded. Non-Python IPython magics use syntax-safe placeholders only in
the shadow document. Python expressions inside %time, %timeit, and %prun stay
visible to LSP, so rename updates identifiers there while protecting prefixes.

Tree-sitter parses each cell in its own language and projects highlight
captures into the visible composite buffer. Missing parsers degrade cleanly.

When nvim-cmp is installed, nvjup adds a buffer-local `nvjup` source because
the ordinary `nvim_lsp` source cannot see clients attached to hidden shadow
buffers. Existing completion sources remain enabled. Pyright automatically
uses a project-root .venv or venv unless `lsp.python_path` overrides it.

The default LSP mappings mirror ordinary code buffers:

gd                      Definition.
gD                      Declaration.
gi                      Implementation.
<Leader>D               Type definition.
gr                      References.
K                       Hover.
<Leader>ls              Signature help.
<C-Space>               Completion in Insert mode.
<Leader>ra              Rename across code cells.
<Leader>ca              Safe code action.
<LocalLeader>ls         Document symbols.

Diagnostics, semantic tokens, locations, and safe WorkspaceEdits are mapped
back from shadow buffers. Edits crossing a cell boundary, synthetic separator,
or IPython placeholder are rejected.

6. KERNEL EXECUTION                                       *nvjup-execution*

Kernel transport runs in a separate Python jupyter_client sidecar. It does not
use pynvim or python3_host_prog. The sidecar starts lazily on first execution.

For Python notebooks, the actual kernel prefers project-root .venv/bin/python
or venv/bin/python with ipykernel, then falls back to a system Python. This is
independent of the sidecar interpreter and global python3 kernelspec. Override
it with `kernel.python_path` or `kernel.system_python`. Non-Python notebooks use
the notebook kernelspec name or `kernel.default_name`.

Batch commands snapshot cell IDs, source, and revisions, skip non-code cells,
and execute sequentially. `execution.stop_on_error` cancels the unsent tail of
a failed batch. Editing a running snapshot preserves its output but marks it
stale with [*]. Output changes and execution counts are persisted by :write.

The sidecar routes stream, execute_result, display_data, update_display_data,
clear_output, error, and input_request messages. Normal stdin uses vim.ui.input;
password input uses inputsecret(). Interrupt and restart are explicit actions.

Cell frames follow jupynvim's labels: the top-right badge is `#N`, while the
bottom border shows the execution count/status and language, for example
`[12] ✓ 0.3s` and `Python`. Runtime duration is measured for executions in the
current session. Other states are queued, running, waiting for input, failed,
cancelled, and stale.

7. RICH STATIC OUTPUTS                                 *nvjup-rich-output*

Stage 4 renders streams, errors, Markdown, sanitized HTML, terminal tables,
and static images. PNG uses Kitty Unicode placeholders. JPEG/PDF use
ImageMagick; sanitized SVG prefers rsvg-convert and falls back to ImageMagick.
Without a compatible Kitty/Ghostty UI, auto mode uses chafa and then a bounded
text fallback. Bare carriage returns update one live tqdm-style progress line.

Image placeholders are anchored to extmark virtual lines, so they follow
scrolling, resizing, folds, and hidden windows without Kitty remote control.
Cached terminal images are deleted when output changes, collapses, clears, or
the notebook closes.

HTML is never executed. SVG containing scripts, event handlers, external
references, entities, embedded objects, or CSS URLs is rejected. Configurable
byte, pixel, conversion-time, memory, disk, and output-size bounds apply.

<Leader>no toggles the inline max_output_lines limit for the current cell.
<Leader>np or :NvJupOutputOpen opens the current cell's untruncated output.
Optional modes are split, vsplit, and tab. See docs/stage4.md for protocol and
security details. :checkhealth nvjup reports the selected backend.

`tqdm.auto` uses ipywidgets in Jupyter kernels. nvjup recognizes the bounded
HTML/HBox/progress model subset and projects its live state as terminal text.

==============================================================================
8. INTERACTIVE OUTPUT                                 *nvjup-plotly*

Stage 6 renders Plotly and safely serialized Bokeh standalone documents in a
dedicated headless Chromium process. Active output is blocked until
:NvJupTrustInteractive grants the current content identity; code or active MIME
changes invalidate it. :NvJupTrustStatus inspects and :NvJupTrustRevoke removes
the grant. Notebook HTML and arbitrary JavaScript are never executed.

Local assets, strict CSP, denied network requests, adaptive CDP screencast PNG
frames, pull fallback, crash replay, and cleanup form the production renderer.
<Leader>nf or :NvJupPlotFocus exports validated content to a mode-0600 temporary
file and opens Awrit in a separate Kitty OS window. Awrit paints raw browser
frames through shared memory and Kitty animation composition without screenshots.
<Leader>nF or :NvJupPlotFocusTui keeps the old 112x40 TUI focus window. Mouse,
wheel, and keyboard input are native in Awrit and forwarded in TUI mode.
:NvJupPlotStatus shows component metrics and renderer state. See docs/stage6.md.

10. CURRENT LIMITATIONS                                 *nvjup-limitations*

Arbitrary widgets, arbitrary HTML/JavaScript, Bokeh server sessions, and Bokeh
payloads incompatible with the locally installed BokehJS are not enabled. PDF
display uses only the first page. Animated images are currently static. Actual Kitty
pixels require a compatible attached terminal UI. Remote Jupyter Server
attachment and kernel-backed completion are also later work. Completion uses
nvim-cmp when available and Neovim's built-in completion UI as a fallback.
